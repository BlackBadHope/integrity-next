## Наблюдавшееся время, не бенчмарк скорости продукта

[benchmarks.json](benchmarks.json) сохраняет существующие однократные замеры установки и приёмки: создание venv, pip install, полный pytest и BOOTSTRAP. Внутреннее время pytest — 22,20 с для Linux 6.1.1 и 161,50 с для Windows 6.1.1; время процесса с обёрткой — 22,50 и 162,69 с соответственно. Для Linux 6.1.0 сохранено только время процесса 23,17 с: pytest не напечатал внутреннюю длительность.

Различаются ОС, Python, виртуализация, набор пропусков и условия загрузки зависимостей. Одна выборка не позволяет заявлять ускорение, сравнивать производительность ОС, вычислять p95 или оценивать задержку recall/admission. Отдельные performance-бенчмарки продукта в этой проверке **NOT_RUN**. Подготовка среды, загрузка исходных архивов, перезагрузка и cleanup в суммы команд не включены.

## История исправления и пропуски

В 6.1.0 буквальный Bash BOOTSTRAP успешно завершался, но относительный architecture-root создавал базу внутри checkout. Это сохраняется как исторический FAIL инструкции. В 6.1.1 Bash и PowerShell примеры выбирают приватный каталог состояния вне checkout; фактическое существование базы и отсутствие перенаправления пути в Windows проверены. Windows-установка 6.1.0 осталась NOT_RUN из-за отказа предпосылки Git; более поздний Windows PASS относится к 6.1.1.

Windows-прогон 6.1.1 первоначально дал **33 PASS / 1 FAIL** на 34 наблюдения (25 команд и 9 утверждений). Наш валидатор ошибочно отвергал OWNER RIGHTS и требовал точного владельца-пользователя для architecture. В сохранённом SDDL фактическим владельцем был доверенный Administrators; OW относится к текущему владельцу объекта. Независимый разбор исходного SDDL подтвердил ложное срабатывание без изменения продукта, прав или повторного запуска тестов. Отдельный строгий ACL-контракт Native Trust прошёл. Исходный FAIL и итог после разбора разделены в results.json; формальный ненулевой exit-code исходного harness не скрывается.

Семантика: [Microsoft: security identifiers](https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/manage/understand-security-identifiers), [SDDL SID strings](https://learn.microsoft.com/en-us/windows/win32/secauthz/sid-strings), [Python 3.12 os.mkdir](https://docs.python.org/3.12/library/os.html#os.mkdir). Проверяемые строки продукта в релизе: src/integrity_guardian/cli.py:1158–1166 (architecture mkdir), src/integrity_guardian/native_trust.py:650–659 (отдельный trust-контракт).

Во всех средах один пропуск относится к приватному literal corpus, который не включён в публичный релиз. В Linux ещё шесть пропусков относятся к Windows redirector/DACL API; в Windows они исполнялись.

## Воспроизведение и границы

Публичный источник: [релиз v6.1.1](https://github.com/BlackBadHope/integrity-next/releases/tag/v6.1.1), commit a727c12f6d2504de5cdfdf7e540ab7837f499146. Примеры: [README](https://github.com/BlackBadHope/integrity-next/blob/v6.1.1/README.md), [BOOTSTRAP](https://github.com/BlackBadHope/integrity-next/blob/v6.1.1/BOOTSTRAP.md). Последовательность приёмки: чистый HOME → новая venv → core install → проверка installed import вне checkout и pip check → команды README → dev extras и один корневой pytest → буквальный shell-пример BOOTSTRAP → независимая проверка физического пути базы и применимых ACL.

- Linux 6.1.1 использовал проверенный release tar.gz вместо Git clone; core был проверен до установки дополнительного SDK. Остальные optional-клиенты NOT_RUN.
- Windows использовал проверенный release ZIP и официальный portable Python NuGet внутри гостя. Выбран явный интерпретатор venv и Scripts в PATH: **буквальный Activate.ps1 NOT_RUN**. Вывод дочерних процессов настроен на UTF-8.
- Windows проверен под административным гостевым аккаунтом. Последующий доступ с пониженным токеном или от отдельного обычного пользователя **NOT_RUN**. Дополнительные 15 дистрибутивов не устанавливались.
- Гостевые среды и временные соединения очищены после сохранения доказательств. Проверяемый продукт исполнялся в изоляции. Рабочие установки, базы и сервисы в эту приёмку не входили.

Пакет содержит только обезличенную проекцию результатов и публичные тестовые логи. Пользовательский контекст, машинные привязки, операционные адреса, базы и закрытые ключи исключены.
