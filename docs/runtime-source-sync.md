# Runtime source consistency

The client-memory distribution 1.8.1 carries the Linux lifecycle repair in its
single canonical Linux resource profile. Slow Native ownership proofs execute
outside the shared custody lock; claim expiry, one-use consumption and final
state comparisons remain enforced. The original producer proof uses the exact
private claim and Native head rather than an invented environment identity.

Typed runtime diagnostics expose bounded static codes, message hashes and safe
frame names. They never publish arbitrary exception messages or prompt content.
The pure generation-navigation helper accepts caller-owned values and performs
no file write, restart, registration, Native action or network operation.

The portable Resource Advisor remains the rc6 advisory implementation. It does
not contain an HTTP dashboard or health endpoint. Its documentation reserves
independent example ports for an optional UI and an Action Log connection, and
requires verifying the service identity at a configured endpoint. An operational
dashboard implementation must not be represented as a version alias of rc6.

Source provenance is recorded by each component's source map and the complete
public export manifest. Deployment configurations, authority grants, live
registrations, personal identifiers and runtime state are outside this tree.
Previously published release archives are immutable; these source changes are
available for a subsequent reviewed release.

## Linux hotfix chain (broker 1.6.1-linux.7, hook 1.8.0-linux.5)

The canonical Linux resources carry the installed Linux hotfix chain. The
broker uses a POSIX transport-start gate and refuses other platforms; the hook
reads the active stdio registration from `config.toml` instead of launching a
second CLI inside the lifecycle deadline, whose budget is 180 seconds. The hook
accepts the current and the immediately previous Linux broker. A repeated
lifecycle dispatch is resolved only by a positive exact canonical receipt, and
Native observation failures are distinguished from supersession. The curator
guard binds the protected admission anchor and the current own open receipt
before the pinned Native reader checks the exact turn. Child lifecycle
notifications never retire the parent's admission.

The public hook keeps its 1.8.0 (memory API 2.11) family, so its Linux revision
is 1.8.0-linux.5 where the installed hook reports 1.7.4-linux.5. The canonical
`core_delivery.py` remains the Windows recovery module; the Linux curator guard
lives only in the Linux broker's embedded Core copy.
